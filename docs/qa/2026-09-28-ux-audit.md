# UX & design audit: dreamproperties.app, 2026-09-28

Reviewed against the `frontend-design` and `estate-agency-design` skills. Evidence:
live site at phone width (375px, where agents work at show houses) plus a read of
`app/globals.css`, `app/layout.tsx` and page components. The desktop layout was judged
from code only (the review browser was too narrow for useful desktop screenshots).

**Verdict:** the bones are good. Strong domain vocabulary, a real signature (the
deeds-office card with its "IN CONVEYANCING" stamp), mono-for-data mostly honoured,
and a clear dashboard. What drags it down is *inconsistency*, not concept: two colour
systems, a font that never loads, ~960 inline styles, and several phone-width breakages.
Fix the system first; most screen-level problems then fall out cheaply.

## P1: broken or misleading (fix first)

1. **Fraunces is used but never loaded.** `layout.tsx` loads only Inter + JetBrains Mono,
   yet ~10 pages set `fontFamily: 'Fraunces', 'Cormorant Garamond', serif` inline
   (pipeline, mandates, compliance, estates, erf-lookup, contacts/[id], valuation-rolls).
   Result: those headings render in the browser's default **Times New Roman**, which is why the
   pipeline and compliance pages look like a different product.
2. **Horizontal overflow on phones.** On dashboard, properties, property record and
   compliance the header stops short of the right edge and a horizontal scrollbar appears,
   so something is wider than the viewport. Likely candidates: the deeds-card stamp
   (absolutely positioned, overhangs its card), the pipeline board, and fixed `min-width`s
   (`globals.css` ~L1426 `min-width: 200px`, ~L2504). Add `overflow-x: clip` to the
   stamp's card and find the true offender with a width audit.
3. **Dashboard "Attention today" collapses addresses on phones.** Rows show "3." and
   "7…" because the red status text takes the width; on 7 The Grove the suburb and
   "45 d past transfer date" overlap. Stack status under the address below ~480px.
4. **Invisible links on compliance header.** "Settings" and "Team" are navy text on the
   navy header, which fails contrast outright. Links on dark headers must use gold or white.
5. **Property record dead end.** "No listing on this property yet — create one first"
   sits next to "Prepare mandate…", but there is no "Create listing" action on the page.
   Every empty state needs the button that resolves it.
6. **Jargon leaks to the user.** "AMBER" (a triage confidence code) is shown as a status
   on the dashboard; "Muni", "SG C0390005…", "ATTACH P24 LISTING" in shouty mono caps.
   Write labels for Bronwyn: "Needs review", "Municipal valuation", "Link Property24 listing".

## P2: system inconsistency (the root cause)

7. **Two colour systems at once.** Brand navy/gold/mist (`--navy #132B84`, `--gold`,
   `--mist #EDF0F8` cool blue-grey page background) *and* the warm "paper" tokens
   (`--paper-*`, `--ink-*`) are both live. Cards are warm paper on a cool blue page;
   status pills mix both. **Decision needed (Simon):** recommended direction is to keep
   Dream's navy + gold as the *brand* (header, primary buttons, signature stamp) and
   make every *surface* warm paper, meaning page background `--paper-0` rather than `--mist`.
   One system, brand on top.
8. **963 inline `style={{}}` blocks** in TSX (MapView 65, compliance 56, Offers 39,
   NewPropertyForm 37…) bypass the tokens, so spacing, type and colour drift page to page.
   Move to CSS classes that consume tokens; worst files first.
9. **184 raw hex values in `globals.css`** (2 511 lines, one file). Tokens exist but aren't
   used consistently. Replace raw hex with tokens; split into `tokens.css`, `base.css`,
   and per-feature modules.
10. **No font tokens.** Add `--font-display / --font-body / --font-mono` and load all
    three with `next/font` (self-hosted, no layout shift, no Google Fonts round-trip).
11. **Buttons have three styles on one card** (property record: bordered sans,
    bordered sans small, navy-outlined mono caps). Define primary / secondary / quiet
    and use only those.
12. **Accessibility floor missing.** Only 3 focus rules and 2 reduced-motion rules in the
    whole stylesheet. Add a global `:focus-visible` ring (gold on navy, navy on paper) and
    wrap all transitions in `prefers-reduced-motion`.

## P3: screen-level UX

13. **Pipeline on phones:** 8 columns side-scrolled with each card carrying ←, → STAGE,
    and a ⋯ select. On a phone use a stage picker (tabs or a select) showing one column,
    and replace the three controls with one "Move to…" action. Show days-in-stage colour
    only when stalled.
14. **Property record hierarchy:** the first screen is admin actions and the deed card;
    the things an agent needs first (status, price, parties, next deadline) are below the
    fold. Order: status + next deadline → parties → agreement money → deed card → documents
    → compliance. Keep the stamp; it's the product's best moment.
15. **Properties list:** cards show "—" for three of four fields on many rows and no status or
    price. Add the listing-status pill and asking price (mono), hide empty fields rather than
    printing dashes, and add search/filter (suburb, status). The list will grow.
16. **Compliance repeats itself:** each party shows a pill "FICA · DOCS IN — NOT VERIFIED"
    *and* the line "Docs in — not verified" beneath it. Keep the pill, drop the line;
    group parties by deal side (sellers / buyers).
17. **Mobile header:** hamburger + logo + ADMIN badge + Sign out crowd a 375px bar. Move
    Sign out into the menu; keep logo + menu + one quick action (e.g. search).
18. **Erf Lookup** pre-renders the whole municipal roll into a dropdown; use type-ahead.

## What to keep

The deeds-office card and stamp (signature moment), mono figures (`R 25 200 000`,
`1043 m²`, deed numbers), the gold hairline under the header, the "Attention today" idea,
SA vocabulary throughout, and the compliance page's clarity of purpose.

## Suggested sequence (plan 018)

1. **System pass (1 PR):** font tokens + `next/font` (Inter body, Fraunces display, JetBrains
   Mono data), page background to paper, global focus + reduced-motion, button trio.
   Fixes #1, #7, #10, #11, #12 everywhere at once.
2. **Phone-width fixes (1 PR):** overflow offender, dashboard rows, compliance link
   contrast, header crowding. Fixes #2, #3, #4, #17.
3. **Copy pass (1 PR):** user-facing labels and empty-state actions. Fixes #5, #6, #16.
4. **Screens, one PR each:** pipeline mobile (#13), property record order (#14),
   properties list (#15).
5. **Ongoing:** retire inline styles file by file as each screen is touched (#8, #9).

Verify each PR at 375px and 1440px with screenshots before merging.
